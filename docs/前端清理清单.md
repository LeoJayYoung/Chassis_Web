# 前端清理与拆分清单

> 状态：**已实施并通过构建验证（2026-10-24）**。
> 行号基于当前版本（`src/stores/robotRuntime.ts` 约 1855 行），仅供参考。

## 0. 已确认的决策

1. ✅ **真实环境下"任务 / 日志 / 定时"只走后端**，前端不再直连 Nav2 下发指令。
2. ✅ **Tasks 页拆成「任务记录 / 巡检计划 / 路线模板」三个 Tab。**
3. ✅ **路线采用"命名模板可复用"**（先保存模板，再基于模板建多个计划）。
4. ✅ **"待核对(unknown)"先只提供「取消」「重新执行」两个人工操作。**

## 4. 拆分方案

`robotRuntime.ts`（1855 行）拆成 4 个文件：

| 新文件 | 装什么 |
|---|---|
| `stores/backendSync.ts` | 后端同步：`refreshBackendData` / `startBackendSubscription` / `upsertBackendRun` / `prependBackendLog` + 9 个映射函数（`#82-#252`） |
| `stores/taskCommands.ts` | 走后台的任务命令：`createBackendTask` + start/pause/continue/cancel/retry/delete 的后端分支 |
| `stores/mock.ts` | mock 专用：`startMockPoseStream` / `updateMockProgress` / `poseAtPathProgress` 等 |
| `stores/robotRuntime.ts` | 只留骨架：状态、computed、对外 action，调用上面三个模块 |

**关键结构对齐**：`runtime.tasks` 拆成 `taskRuns` + `schedules`（对应后端 `task_runs` / `schedules` 两张表），支撑 Tasks 页三个 Tab。

## 5. 执行顺序

1. 先修第 1 部分的 3 个 bug（让"每天巡检"先能用）。
2. 再做第 4 部分的拆分（数据结构和文件先理顺）。
3. 最后删第 2 部分的死代码（此时已无引用，删得干净）。

> 原则：每一步做完都能跑通，不出现"删一半跑不起来"的尴尬期。

## 6. 实施结果

- `runtime.tasks` 已拆为 `taskRuns / schedules / routeTemplates`。
- Tasks 页已拆成「任务记录 / 巡检计划 / 路线模板」三个 Tab。
- `unknown` 已作为黄色「待核对」独立状态，仅提供取消和重新执行。
- 每日、间隔、指定日期三种计划已分别校验。
- 循环计划与任务执行记录已分离，计划触发后仍保留。
- 路线模板可命名保存并复用于多个计划。
- `runNow` 映射为「手动执行计划」，保留 `scheduleId` 追溯关系。
- 后端已广播 `schedule-created / schedule-updated / schedule-deleted`。
- 已删除前端 Nav2 Action 直连客户端、`real` 数据源和对应环境变量。
- 后端模式 Logs 页只接收持久化日志；本地 `appendLog` 仅用于 Mock。
- STM32 `std_msgs/msg/String` 已优先读取 `msg.data`。
- SSE 重连成功后会清除 `backendError`。
